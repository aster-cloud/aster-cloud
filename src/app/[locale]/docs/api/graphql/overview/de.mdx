# GraphQL API – Überblick

Die Aster Policy Engine stellt eine GraphQL API für das Abfragen und Verwalten von Policies bereit. Sie basiert auf **SmallRye GraphQL** (der MicroProfile-GraphQL-Implementierung) und bietet das volle Spektrum der MicroProfile-GraphQL-Funktionen einschließlich eingebauter Introspektion, Typsicherheit und eines gehosteten Schema-Endpunkts.

## Endpunkt

| Zweck | URL |
|---------|-----|
| Query / Mutation-Ausführung | `POST /graphql` |
| Schema (SDL) | `GET /api/graphql/schema.graphql` |

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `Content-Type` | `application/json` | Ja |
| `X-Tenant-Id` | Mandanten-Identifikator-String | Ja |
| `Idempotency-Key` | Vom Client generierter eindeutiger String (UUID empfohlen) | Nur Mutationen |

<Callout type="tip" title="Idempotency-Key">
Das Bereitstellen eines `Idempotency-Key` bei Mutation-Anfragen stellt sicher, dass das erneute Senden einer fehlgeschlagenen oder zeitlich abgelaufenen Anfrage die Operation nicht ein zweites Mal anwendet. Der Server cached das Mutation-Ergebnis 24 Stunden lang unter diesem Schlüssel. Dieser Header ist optional, aber für Schreiboperationen dringend empfohlen.
</Callout>

## Anfrageformat

Alle Anfragen müssen HTTP `POST` mit einem JSON-Body sein, der der GraphQL-over-HTTP-Spezifikation entspricht:

```json
{
  "query": "query { ... }",
  "variables": {},
  "operationName": "OptionalOperationName"
}
```

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `query` | `string` | Ja | GraphQL-Dokument mit der auszuführenden Operation. |
| `variables` | `object` | Nein | Werte für benannte Variablen, die in `query` referenziert werden. |
| `operationName` | `string` | Nein | Disambiguiert, welche Operation ausgeführt werden soll, wenn `query` mehrere benannte Operationen enthält. |

## Antwortformat

```json
{
  "data": {},
  "errors": []
}
```

Für alle wohlgeformten GraphQL-Antworten wird der HTTP-Status `200 OK` zurückgegeben, einschließlich Teilerfolgen. Prüfen Sie immer das `errors`-Array — ein nicht leerer Wert zeigt an, dass ein oder mehrere Feld-Resolver auf einen Fehler gestoßen sind, auch wenn `data` teilweise befüllt ist.

## Schema

Laden Sie das vollständige Schema im SDL-Format herunter:

<CodeGroup>

```bash [curl]
curl -X GET https://policy.aster-lang.dev/api/graphql/schema.graphql \
  -H "Authorization: Bearer <token>"
```

</CodeGroup>

## Fehlerbehandlung

GraphQL-Fehler folgen dem [Fehlerformat der GraphQL-Spezifikation](https://spec.graphql.org/October2021/#sec-Errors):

```json
{
  "data": null,
  "errors": [
    {
      "message": "Policy not found",
      "locations": [{ "line": 2, "column": 3 }],
      "path": ["getPolicy"],
      "extensions": {
        "code": "NOT_FOUND",
        "classification": "DataFetchingException"
      }
    }
  ]
}
```

| Extension-Feld | Beschreibung |
|-----------------|-------------|
| `code` | Maschinenlesbarer Fehlercode (z. B. `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`). |
| `classification` | SmallRye-GraphQL-Fehlerklassifizierung. |

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | GraphQL-Antwort zurückgegeben (prüfen Sie `errors` auf Teilfehler). |
| `400 Bad Request` | Request-Body ist kein gültiges JSON oder das GraphQL-Dokument ist syntaktisch ungültig. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die erforderliche Rolle für die angeforderte Operation. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler, bevor die GraphQL-Schicht antworten konnte. |
