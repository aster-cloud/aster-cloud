# Workflow-Status

Rufen Sie den aktuellen materialisierten Status eines Workflows ab. Der Status wird aus dem Event-Log des Workflows abgeleitet und kann durch einen periodischen Snapshot ergänzt werden, um Lesevorgänge zu beschleunigen. Nutzen Sie diesen Endpunkt, wenn Sie den neuesten Status und das Ergebnis benötigen, ohne die vollständige Ereignishistorie abzurufen.

## Endpunkt

`GET /api/v1/workflows/{workflowId}/state`

## Erforderliche Rolle

`MEMBER`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

## Pfad-Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `workflowId` | `string` | Der eindeutige Bezeichner des Workflows. |

## Response-Body

```json
{
  "workflowId": "wf-abc123",
  "status": "COMPLETED",
  "lastEventSeq": 5,
  "result": {
    "eligible": true,
    "approvedAmount": 25000
  },
  "snapshot": {
    "intermediateState": "..."
  },
  "snapshotSeq": 3,
  "createdAt": "2024-01-15T10:29:58Z",
  "updatedAt": "2024-01-15T10:30:01Z"
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `workflowId` | `string` | Eindeutiger Bezeichner des Workflows. |
| `status` | `string` | Aktueller Lifecycle-Status. Siehe [Statuswerte](#status-values) unten. |
| `lastEventSeq` | `integer` | Sequenznummer des zuletzt angewendeten Ereignisses. |
| `result` | `any \| null` | Vom Workflow erzeugte finale Ausgabe. Befüllt, sobald `status` einen Endzustand erreicht (`COMPLETED`, `FAILED`, `COMPENSATED`, `COMPENSATION_FAILED`). `null` für nicht abgeschlossene Workflows. |
| `snapshot` | `object \| null` | Opaker Snapshot des Zwischenzustands zur Beschleunigung des Event-Replays. `null`, wenn noch kein Snapshot erstellt wurde. |
| `snapshotSeq` | `integer \| null` | Sequenznummer, bei der der Snapshot erstellt wurde. `null`, wenn `snapshot` `null` ist. |
| `createdAt` | `string` | ISO 8601 Zeitstempel, wann der Workflow erstellt wurde. |
| `updatedAt` | `string` | ISO 8601 Zeitstempel der letzten Statusänderung. |

## Statuswerte

| Status | Endzustand | Beschreibung |
|--------|----------|-------------|
| `READY` | Nein | Workflow wurde erstellt, aber noch nicht gestartet. |
| `RUNNING` | Nein | Workflow läuft gerade. |
| `COMPLETED` | Ja | Workflow erfolgreich abgeschlossen. `result` ist befüllt. |
| `FAILED` | Ja | Workflow wurde aufgrund eines nicht wiederherstellbaren Fehlers beendet. |
| `COMPENSATING` | Nein | Workflow führt Kompensationsschritte (Rollback) aus. |
| `COMPENSATED` | Ja | Kompensation erfolgreich abgeschlossen. |
| `COMPENSATION_FAILED` | Ja | Auch die Kompensationsschritte schlugen fehl. Manuelles Eingreifen kann erforderlich sein. |

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Anfrage erfolgreich. Gibt den aktuellen Workflow-Status zurück. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `MEMBER`-Rolle, oder der Workflow gehört einem anderen Mandanten. |
| `404 Not Found` | Kein Workflow mit der angegebenen `workflowId` gefunden. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler. |

## Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/workflows/wf-abc123/state" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const workflowId = 'wf-abc123';
const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/workflows/${workflowId}/state`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const state = await response.json();

if (state.status === 'COMPLETED') {
  console.log('Workflow result:', state.result);
} else if (state.status === 'FAILED') {
  console.error('Workflow failed. Last event sequence:', state.lastEventSeq);
}
```

</CodeGroup>
