# Workflow-Metriken

Operative Endpunkte zur Überwachung der Workflow-Gesundheit über den Mandanten hinweg. Verwenden Sie diese zum Erstellen von Dashboards, Einrichten von Alarmschwellen oder Identifizieren festgefahrener Workflows.

## Erforderliche Rolle

`MEMBER`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

---

## Aggregierte Metriken

Anzahl der Workflows gruppiert nach Status abrufen. Dies liefert einen Überblick über den aktuellen Betriebszustand des Systems.

### Endpunkt

`GET /api/v1/workflows/metrics`

### Response-Body

```json
{
  "READY": 14,
  "RUNNING": 203,
  "COMPLETED": 98421,
  "FAILED": 37,
  "COMPENSATING": 2,
  "COMPENSATED": 18,
  "COMPENSATION_FAILED": 1
}
```

Die Antwort ist ein flaches Objekt, das jeden Status auf seine aktuelle Workflow-Anzahl abbildet. Alle Status-Schlüssel sind immer vorhanden, mit einem Wert von `0`, wenn keine Workflows in diesem Zustand existieren.

### Statuswerte

| Status | Endzustand | Beschreibung |
|--------|----------|-------------|
| `READY` | Nein | Erstellt, aber noch nicht gestartet. |
| `RUNNING` | Nein | Wird aktiv ausgeführt. |
| `COMPLETED` | Ja | Erfolgreich abgeschlossen. |
| `FAILED` | Ja | Aufgrund eines nicht wiederherstellbaren Fehlers beendet. |
| `COMPENSATING` | Nein | Kompensations-Schritte (Rollback) werden ausgeführt. |
| `COMPENSATED` | Ja | Kompensation erfolgreich abgeschlossen. |
| `COMPENSATION_FAILED` | Ja | Auch die Kompensations-Schritte schlugen fehl. |

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/workflows/metrics" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/workflows/metrics',
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const metrics = await response.json();

// Alert if any workflows are stuck in a compensation failure state
if (metrics.COMPENSATION_FAILED > 0) {
  console.warn(`${metrics.COMPENSATION_FAILED} workflow(s) require manual intervention`);
}
```

</CodeGroup>

## Workflows nach Status auflisten

Eine Liste der Workflow-IDs abrufen, die sich aktuell in einem gegebenen Status befinden. Nützlich, um nach Erkennen einer Auffälligkeit aus den aggregierten Metriken in spezifische Workflows einzusteigen.

### Endpunkt

`GET /api/v1/workflows/by-status/{status}`

### Pfad-Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `status` | `string` | Der Workflow-Status, nach dem gefiltert werden soll. Muss einer der oben in der Tabelle der Statuswerte aufgeführten Werte sein. |

### Query-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `limit` | `integer` | Nein | Maximale Anzahl zurückzugebender Workflow-IDs. Standard: `100`. Der Server kann seine eigene maximale Obergrenze erzwingen. |

### Response-Body

```json
{
  "status": "RUNNING",
  "workflowIds": [
    "wf-abc123",
    "wf-def456",
    "wf-ghi789"
  ],
  "count": 3
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `status` | `string` | Der angeforderte Status (spiegelt den Pfad-Parameter). |
| `workflowIds` | `string[]` | Liste der übereinstimmenden Workflow-Bezeichner, absteigend nach Erstellungszeit sortiert. |
| `count` | `integer` | Anzahl der in dieser Antwort zurückgegebenen IDs. Kann kleiner als die Gesamtsumme sein, wenn die Ergebnisse durch `limit` begrenzt wurden. |

### Beispiele

<CodeGroup>

```bash [curl]
# List up to 100 running workflows (default limit)
curl -X GET "https://policy.aster-lang.dev/api/v1/workflows/by-status/RUNNING" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"

# List up to 10 failed workflows
curl -X GET "https://policy.aster-lang.dev/api/v1/workflows/by-status/FAILED?limit=10" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
async function getWorkflowsByStatus(status, limit = 100) {
  const params = new URLSearchParams({ limit: String(limit) });
  const response = await fetch(
    `https://policy.aster-lang.dev/api/v1/workflows/by-status/${status}?${params}`,
    {
      headers: {
        Authorization: 'Bearer <token>',
        'X-Tenant-ID': 'acme-corp',
      },
    }
  );
  return response.json();
}

// Inspect the first 10 failed workflows
const { workflowIds } = await getWorkflowsByStatus('FAILED', 10);

for (const id of workflowIds) {
  const stateRes = await fetch(
    `https://policy.aster-lang.dev/api/v1/workflows/${id}/state`,
    { headers: { Authorization: 'Bearer <token>', 'X-Tenant-ID': 'acme-corp' } }
  );
  const state = await stateRes.json();
  console.log(id, state.updatedAt, state.lastEventSeq);
}
```

</CodeGroup>

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Anfrage erfolgreich. |
| `400 Bad Request` | Ungültiger `status`-Wert oder fehlerhafter `limit`-Parameter. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `MEMBER`-Rolle. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler. |
