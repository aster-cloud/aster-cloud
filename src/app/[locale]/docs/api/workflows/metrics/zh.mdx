# 工作流指标

用于跨租户监控工作流健康的操作性端点。使用这些端点构建仪表板、设置告警阈值或识别卡住的工作流。

## 必需角色

`MEMBER`

## 请求头

| 请求头 | 值 | 必需 |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | 是 |
| `X-Tenant-ID` | 租户标识符字符串 | 是 |

---

## 聚合指标

按状态分组获取工作流数量。这提供了系统当前操作状态的高层快照。

### 端点

`GET /api/v1/workflows/metrics`

### 响应体

```json
{
  "READY": 14,
  "RUNNING": 203,
  "COMPLETED": 98421,
  "FAILED": 37,
  "COMPENSATING": 2,
  "COMPENSATED": 18,
  "COMPENSATION_FAILED": 1
}
```

响应是一个扁平对象，将每个状态映射到其当前工作流数量。所有状态键始终存在，没有该状态的工作流时值为 `0`。

### 状态值

| 状态 | 终态 | 描述 |
|--------|----------|-------------|
| `READY` | 否 | 已创建但尚未启动。 |
| `RUNNING` | 否 | 正在执行。 |
| `COMPLETED` | 是 | 成功完成。 |
| `FAILED` | 是 | 因不可恢复的错误终止。 |
| `COMPENSATING` | 否 | 正在执行补偿（回滚）步骤。 |
| `COMPENSATED` | 是 | 补偿成功完成。 |
| `COMPENSATION_FAILED` | 是 | 补偿步骤也失败。 |

### 示例

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/workflows/metrics" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/workflows/metrics',
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const metrics = await response.json();

// Alert if any workflows are stuck in a compensation failure state
if (metrics.COMPENSATION_FAILED > 0) {
  console.warn(`${metrics.COMPENSATION_FAILED} workflow(s) require manual intervention`);
}
```

</CodeGroup>

## 按状态列出工作流

获取当前处于给定状态的工作流 ID 列表。在从聚合指标中识别出关注点后，用于深入特定工作流。

### 端点

`GET /api/v1/workflows/by-status/{status}`

### 路径参数

| 参数 | 类型 | 描述 |
|-----------|------|-------------|
| `status` | `string` | 要筛选的工作流状态。必须是上方状态值表中列出的值之一。 |

### 查询参数

| 参数 | 类型 | 必需 | 描述 |
|-----------|------|----------|-------------|
| `limit` | `integer` | 否 | 返回的最大工作流 ID 数量。默认为 `100`。服务器可能强制其自身的最大上限。 |

### 响应体

```json
{
  "status": "RUNNING",
  "workflowIds": [
    "wf-abc123",
    "wf-def456",
    "wf-ghi789"
  ],
  "count": 3
}
```

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `status` | `string` | 请求的状态（与路径参数一致）。 |
| `workflowIds` | `string[]` | 匹配的工作流标识符列表，按创建时间降序排列。 |
| `count` | `integer` | 此响应中返回的 ID 数量。若结果被 `limit` 截断则可能小于总数。 |

### 示例

<CodeGroup>

```bash [curl]
# List up to 100 running workflows (default limit)
curl -X GET "https://policy.aster-lang.dev/api/v1/workflows/by-status/RUNNING" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"

# List up to 10 failed workflows
curl -X GET "https://policy.aster-lang.dev/api/v1/workflows/by-status/FAILED?limit=10" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
async function getWorkflowsByStatus(status, limit = 100) {
  const params = new URLSearchParams({ limit: String(limit) });
  const response = await fetch(
    `https://policy.aster-lang.dev/api/v1/workflows/by-status/${status}?${params}`,
    {
      headers: {
        Authorization: 'Bearer <token>',
        'X-Tenant-ID': 'acme-corp',
      },
    }
  );
  return response.json();
}

// Inspect the first 10 failed workflows
const { workflowIds } = await getWorkflowsByStatus('FAILED', 10);

for (const id of workflowIds) {
  const stateRes = await fetch(
    `https://policy.aster-lang.dev/api/v1/workflows/${id}/state`,
    { headers: { Authorization: 'Bearer <token>', 'X-Tenant-ID': 'acme-corp' } }
  );
  const state = await stateRes.json();
  console.log(id, state.updatedAt, state.lastEventSeq);
}
```

</CodeGroup>

## HTTP 状态码

| 状态 | 含义 |
|--------|---------|
| `200 OK` | 请求成功。 |
| `400 Bad Request` | `status` 值无效或 `limit` 参数格式错误。 |
| `401 Unauthorized` | 缺少或无效的 Bearer token。 |
| `403 Forbidden` | Token 有效但调用者缺少 `MEMBER` 角色。 |
| `500 Internal Server Error` | 非预期的引擎故障。 |
