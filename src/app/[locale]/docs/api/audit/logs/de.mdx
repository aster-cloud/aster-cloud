# Audit-Logs

<Callout type="tip" title="Geltungsbereich">
Diese Endpunkte werden von **aster-api** (der Policy-Engine) bereitgestellt und umfassen Policy-Ausführungsereignisse, die SHA-256-Hash-verkettet sind. Das **aster-cloud** SaaS-Dashboard führt ein separates, nicht verkettetes Aktivitätslog für UI-Ereignisse (Benutzeranmeldungen, Tarifänderungen, Mitglieder-Einladungen); dieses Aktivitätslog wird nicht über diese API bereitgestellt.
</Callout>

Audit-Log-Einträge für Ereignisse abrufen, die von der Policy-Engine aufgezeichnet wurden. Alle Endpunkte in diesem Abschnitt erfordern die `ADMIN`-Rolle.

## Erforderliche Rolle

`ADMIN`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

---

## Alle Audit-Logs abrufen

Eine Liste aller Audit-Log-Einträge für den Mandanten abrufen, absteigend nach Ereigniszeit sortiert.

### Endpunkt

`GET /api/v1/audit`

### Response-Body

```json
[
  {
    "id": "string",
    "eventType": "string",
    "policyModule": "string",
    "policyFunction": "string",
    "actorId": "string",
    "occurredAt": "2024-01-15T10:30:00Z",
    "payload": {},
    "hash": "string",
    "previousHash": "string"
  }
]
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `id` | `string` | Eindeutiger Audit-Datensatz-Bezeichner. |
| `eventType` | `string` | Der Typ des aufgezeichneten Ereignisses (z. B. `POLICY_EVALUATED`, `POLICY_DEPLOYED`). |
| `policyModule` | `string` | Mit dem Ereignis verbundener Modulname, falls zutreffend. |
| `policyFunction` | `string` | Mit dem Ereignis verbundener Funktionsname, falls zutreffend. |
| `actorId` | `string` | Bezeichner des Benutzers oder Service-Principals, der das Ereignis ausgelöst hat. |
| `occurredAt` | `string` | ISO 8601 Zeitstempel, wann das Ereignis stattfand. |
| `payload` | `object` | Ereignisspezifische Metadaten. Die Struktur variiert je `eventType`. |
| `hash` | `string` | SHA-256-Hash des Inhalts dieses Datensatzes, verwendet für die Ketten-Integritätsprüfung. |
| `previousHash` | `string` | Hash des unmittelbar vorangegangenen Audit-Datensatzes, der die Hash-Kette bildet. |

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET https://policy.aster-lang.dev/api/v1/audit \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/audit',
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const logs = await response.json();
```

</CodeGroup>

## Nach Ereignistyp filtern

Audit-Log-Einträge gefiltert nach einem bestimmten Ereignistyp abrufen.

### Endpunkt

`GET /api/v1/audit/type/{eventType}`

### Pfad-Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `eventType` | `string` | Der Ereignistyp, nach dem gefiltert werden soll (z. B. `POLICY_EVALUATED`, `POLICY_DEPLOYED`, `POLICY_ROLLED_BACK`). |

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET https://policy.aster-lang.dev/api/v1/audit/type/POLICY_DEPLOYED \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const eventType = 'POLICY_DEPLOYED';
const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/audit/type/${eventType}`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const logs = await response.json();
```

</CodeGroup>

## Nach Policy filtern

Audit-Log-Einträge für eine spezifische Kombination aus Policy-Modul und Funktion abrufen.

### Endpunkt

`GET /api/v1/audit/policy/{policyModule}/{policyFunction}`

### Pfad-Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `policyModule` | `string` | Der vollqualifizierte Modulname (z. B. `Loan.Approval`). |
| `policyFunction` | `string` | Der Funktionsname innerhalb des Moduls (z. B. `isEligible`). |

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/audit/policy/Loan.Approval/isEligible" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const policyModule = 'Loan.Approval';
const policyFunction = 'isEligible';
const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/audit/policy/${policyModule}/${policyFunction}`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const logs = await response.json();
```

</CodeGroup>

## Nach Zeitbereich filtern

Audit-Log-Einträge innerhalb eines spezifischen Zeitfensters abrufen.

### Endpunkt

`GET /api/v1/audit/range`

### Query-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `startTime` | `string` | Ja | ISO 8601 Startzeitstempel (inklusive). |
| `endTime` | `string` | Ja | ISO 8601 Endzeitstempel (inklusive). |

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/audit/range?startTime=2024-01-01T00:00:00Z&endTime=2024-01-31T23:59:59Z" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const params = new URLSearchParams({
  startTime: '2024-01-01T00:00:00Z',
  endTime:   '2024-01-31T23:59:59Z',
});

const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/audit/range?${params}`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const logs = await response.json();
```

</CodeGroup>

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Anfrage erfolgreich. Gibt ein Array von Audit-Log-Einträgen zurück (kann leer sein). |
| `400 Bad Request` | Fehlende oder fehlerhafte Query-Parameter. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `ADMIN`-Rolle. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler. |
