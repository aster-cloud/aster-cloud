# Hash-Ketten-Verifizierung

Verifizieren Sie die Integrität der Audit-Log-Hash-Kette über ein angegebenes Zeitfenster. Das Audit-Log ist als Hash-Kette strukturiert — jeder Datensatz enthält den Hash des vorherigen Datensatzes — wodurch es manipulationssicher wird. Dieser Endpunkt durchläuft die Kette und meldet, ob jedes Glied gültig ist.

## Endpunkt

`GET /api/v1/audit/verify-chain`

## Erforderliche Rolle

`ADMIN`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

## Query-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `start` | `string` | Ja | ISO 8601 Startzeitstempel (inklusive). |
| `end` | `string` | Ja | ISO 8601 Endzeitstempel (inklusive). |

<Callout type="warning" title="Limit für Zeitfenster">
Das angeforderte Fenster (`end` minus `start`) darf **30 Tage** nicht überschreiten. Anfragen über einen längeren Zeitraum werden mit `400 Bad Request` abgelehnt.
</Callout>

## Response-Body

```json
{
  "valid": true,
  "brokenAt": null,
  "reason": null,
  "recordsVerified": 4821
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `valid` | `boolean` | `true`, wenn jeder Datensatz im Fenster eine ununterbrochene Hash-Kette bildet; `false`, wenn ein Glied ungültig ist oder fehlt. |
| `brokenAt` | `string \| null` | ISO 8601 Zeitstempel des ersten Datensatzes, bei dem die Kette bricht. `null`, wenn `valid` `true` ist. |
| `reason` | `string \| null` | Menschenlesbare Beschreibung, warum die Kette gebrochen ist. `null`, wenn `valid` `true` ist. |
| `recordsVerified` | `number` | Gesamtzahl der Audit-Datensätze, die während der Verifizierung geprüft wurden. |

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Verifizierung abgeschlossen. Prüfen Sie `valid`, um die Ketten-Integrität zu bestimmen. |
| `400 Bad Request` | Fehlende Parameter, fehlerhafte Zeitstempel oder angefordertes Fenster überschreitet das 30-Tage-Limit. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `ADMIN`-Rolle. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler während der Verifizierung. |

## Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/audit/verify-chain?start=2024-01-01T00:00:00Z&end=2024-01-31T23:59:59Z" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const params = new URLSearchParams({
  start: '2024-01-01T00:00:00Z',
  end:   '2024-01-31T23:59:59Z',
});

const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/audit/verify-chain?${params}`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const result = await response.json();

if (!result.valid) {
  console.error(`Chain broken at ${result.brokenAt}: ${result.reason}`);
}
```

</CodeGroup>

### Beispiel-Antwort — Gültige Kette

```json
{
  "valid": true,
  "brokenAt": null,
  "reason": null,
  "recordsVerified": 4821
}
```

### Beispiel-Antwort — Gebrochene Kette

```json
{
  "valid": false,
  "brokenAt": "2024-01-14T08:22:11Z",
  "reason": "Hash mismatch: stored hash does not match recomputed hash for record id=a3f9c1d2",
  "recordsVerified": 512
}
```
