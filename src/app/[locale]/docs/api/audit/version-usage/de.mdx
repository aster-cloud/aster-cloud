# Versionsnutzungs-Audit

Untersuchen, wie eine bestimmte Policy-Version in der Produktion verwendet wird: welche Workflows sie aufgerufen haben, wann die Evaluierungen stattfanden, welche Auswirkungen ein Rollback hätte und kumulative Nutzungsstatistiken im Zeitverlauf.

## Erforderliche Rolle

`ADMIN`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

---

## Workflow-Nutzung

Eine paginierte Liste von Workflow-Aufrufen abrufen, die eine bestimmte Policy-Version verwendet haben.

### Endpunkt

`GET /api/v1/audit/policy-versions/{versionId}/usage`

### Pfad-Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `versionId` | `string` | Policy-Versions-Identifikator. |

### Query-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `status` | `string` | Nein | Workflows nach Status filtern. Einer von: `READY`, `RUNNING`, `COMPLETED`, `FAILED`, `COMPENSATING`, `COMPENSATED`, `COMPENSATION_FAILED`. |
| `page` | `integer` | Nein | Nullbasierter Seitenindex. Standard: `0`. |
| `size` | `integer` | Nein | Anzahl der Datensätze pro Seite. Standard: `20`. |

### Response-Body

```json
{
  "content": [
    {
      "workflowId": "string",
      "status": "COMPLETED",
      "policyModule": "string",
      "policyFunction": "string",
      "invokedAt": "2024-01-15T10:30:00Z"
    }
  ],
  "totalElements": 1024,
  "totalPages": 52,
  "page": 0,
  "size": 20
}
```

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/audit/policy-versions/v-abc123/usage?status=COMPLETED&page=0&size=20" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const versionId = 'v-abc123';
const params = new URLSearchParams({
  status: 'COMPLETED',
  page: '0',
  size: '20',
});

const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/audit/policy-versions/${versionId}/usage?${params}`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const data = await response.json();
// data.content → array of workflow usage records
// data.totalElements → total count across all pages
```

</CodeGroup>

### Endpunkt

`GET /api/v1/audit/policy-versions/{versionId}/timeline`

### Pfad-Parameter

|-----------|------|-------------|
| `versionId` | `string` | Policy-Versions-Identifikator. |

### Query-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `from` | `string` | Nein | ISO 8601 Startzeitstempel. Standard: vor 30 Tagen. |
| `to` | `string` | Nein | ISO 8601 Endzeitstempel. Standard: jetzt. |
| `page` | `integer` | Nein | Nullbasierter Seitenindex. Standard: `0`. |
| `size` | `integer` | Nein | Anzahl der Datensätze pro Seite. Standard: `20`. |

```json
{
```

## Rollback-Auswirkungsbewertung

Die Auswirkungen eines Rollbacks einer bestimmten Policy-Version bewerten. Die Antwort listet die Anzahl der aktiven Workflows auf, die betroffen wären, sowie deren aktuellen Status.

### Endpunkt

`GET /api/v1/audit/policy-versions/{versionId}/impact`

### Pfad-Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `versionId` | `string` | Identifikator der zu bewertenden Policy-Version. |

### Response-Body

```json
{
  "versionId": "v-abc123",
  "affectedWorkflows": 37,
  "byStatus": {
    "RUNNING": 12,
    "COMPENSATING": 3,
    "COMPLETED": 22
  },
  "estimatedRisk": "MEDIUM"
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `versionId` | `string` | Die bewertete Version. |
| `affectedWorkflows` | `number` | Gesamtzahl der Workflows, die diese Version aufgerufen haben. |
| `byStatus` | `object` | Aufschlüsselung der betroffenen Workflows nach aktuellem Status. |
| `estimatedRisk` | `string` | Risikostufe des Rollbacks: `LOW`, `MEDIUM` oder `HIGH`. Abgeleitet aus dem Anteil der Workflows in nicht-finalen Zuständen. |

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/audit/policy-versions/v-abc123/impact" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const versionId = 'v-abc123';
const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/audit/policy-versions/${versionId}/impact`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const impact = await response.json();
console.log(`Risk level: ${impact.estimatedRisk}`);
console.log(`Active workflows affected: ${impact.byStatus.RUNNING ?? 0}`);
```

</CodeGroup>

## Aggregierte Nutzungsstatistiken

Nach Zeitintervallen gruppierte Nutzungsstatistiken für eine Policy-Version abrufen, geeignet zur Darstellung von Trends im Zeitverlauf.

### Endpunkt

`GET /api/v1/audit/stats/version-usage`

### Query-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `versionId` | `string` | Ja | Policy-Versions-Identifikator. |
| `granularity` | `string` | Ja | Bucket-Größe. Einer von: `hour`, `day`, `week`, `month`. |
| `from` | `string` | Nein | ISO 8601 Startzeitstempel. Standard: vor 30 Tagen. |
| `to` | `string` | Nein | ISO 8601 Endzeitstempel. Standard: jetzt. |

<Callout type="warning" title="Zeitfenster-Limit">
Das angeforderte Fenster (`to` minus `from`) darf **90 Tage** nicht überschreiten. Anfragen, die diese Dauer überschreiten, geben `400 Bad Request` zurück.
</Callout>

### Response-Body

```json
{
  "versionId": "v-abc123",
  "granularity": "day",
  "from": "2024-01-01T00:00:00Z",
  "to": "2024-01-31T23:59:59Z",
  "buckets": [
    {
      "timestamp": "2024-01-01T00:00:00Z",
      "count": 342,
      "avgExecutionTimeMs": 8.4,
      "failureRate": 0.012
    }
  ]
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `buckets[].timestamp` | `string` | Startzeitpunkt des Buckets (ISO 8601). |
| `buckets[].count` | `number` | Anzahl der Evaluierungen innerhalb des Buckets. |
| `buckets[].avgExecutionTimeMs` | `number` | Durchschnittliche Policy-Ausführungszeit in Millisekunden. |
| `buckets[].failureRate` | `number` | Anteil fehlgeschlagener Evaluierungen (0.0 bis 1.0). |

### Beispiele

<CodeGroup>

```bash [curl]
curl -X GET "https://policy.aster-lang.dev/api/v1/audit/stats/version-usage?versionId=v-abc123&granularity=day&from=2024-01-01T00:00:00Z&to=2024-01-31T23:59:59Z" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const params = new URLSearchParams({
  versionId:   'v-abc123',
  granularity: 'day',
  from:        '2024-01-01T00:00:00Z',
  to:          '2024-01-31T23:59:59Z',
});

const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/audit/stats/version-usage?${params}`,
  {
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const stats = await response.json();
// stats.buckets → time-series array for charting
```

</CodeGroup>

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Anfrage erfolgreich. |
| `400 Bad Request` | Fehlender Pflichtparameter, fehlerhaft formatierter Zeitstempel oder Fenster überschreitet das Limit. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `ADMIN`-Rolle. |
| `404 Not Found` | Keine Policy-Version mit der angegebenen `versionId` gefunden. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler. |
