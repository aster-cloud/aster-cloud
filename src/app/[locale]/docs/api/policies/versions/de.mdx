# Policy-Versionshistorie abrufen

Rufen Sie die vollständige Versionshistorie für eine Policy ab, die durch ihre interne Policy-ID identifiziert wird. Jeder Eintrag in der Antwort repräsentiert eine eigenständige gespeicherte Version, einschließlich der aktuell aktiven Version.

## Endpunkt

`GET /api/v1/policies/{policyId}/versions`

## Erforderliche Rolle

`MEMBER`

## Pfad-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `policyId` | `string` | Ja | Die interne UUID der Policy-Ressource. Beziehen Sie diesen Wert aus der Policy-Management-API oder dem Aster-Dashboard. |

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

## Request-Body

Keiner.

## Response-Body

Ein Array von Versions-Objekten, aufsteigend nach Versionsnummer sortiert.

```json
[
  {
    "version": 1,
    "active": false,
    "moduleName": "string",
    "functionName": "string",
    "createdAt": "ISO8601",
    "createdBy": "string",
    "notes": "string"
  }
]
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `version` | `number` | Monoton steigende ganze Versionsnummer. Version `1` ist die Erstbereitstellung. |
| `active` | `boolean` | Genau ein Eintrag im Array ist `true` — die Version, die aktuell Evaluierungsanfragen bedient. |
| `moduleName` | `string` | Der in dieser Version des Policy-Quellcodes deklarierte CNL-Modulname. |
| `functionName` | `string` | Der primäre Funktionsname für diese Version der Policy. |
| `createdAt` | `string` | ISO 8601 Zeitstempel, der festhält, wann diese Version gespeichert wurde (z. B. `"2024-03-15T09:30:00Z"`). |
| `createdBy` | `string` | Bezeichner (E-Mail oder Benutzer-ID) des Prinzipals, der diese Version erstellt hat. |
| `notes` | `string` | Optionale menschenlesbare Bereitstellungs-Notizen, die bei der Erstellung der Version angehängt wurden. Leerer String, falls keine Notizen angegeben wurden. |

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Versionshistorie zurückgegeben. Ein leeres Array bedeutet, dass die Policy existiert, aber keine aufgezeichneten Versionen hat. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `MEMBER`-Rolle. |
| `404 Not Found` | Keine Policy für die angegebene `policyId` innerhalb des Mandanten gefunden. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler. |

## Beispiele

<CodeGroup>

```bash [curl]
curl -X GET \
  "https://policy.aster-lang.dev/api/v1/policies/d4e5f6a7-b8c9-4d0e-1f2a-3b4c5d6e7f8a/versions" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-ID: acme-corp"
```

```js [JavaScript]
const policyId = 'd4e5f6a7-b8c9-4d0e-1f2a-3b4c5d6e7f8a';

const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/policies/${policyId}/versions`,
  {
    method: 'GET',
    headers: {
      Authorization: 'Bearer <token>',
      'X-Tenant-ID': 'acme-corp',
    },
  }
);

const versions = await response.json();

const active = versions.find((v) => v.active);
console.log(`Active version: ${active?.version}`);

versions.forEach((v) => {
  const marker = v.active ? ' [ACTIVE]' : '';
  console.log(`v${v.version}${marker} — ${v.createdAt} by ${v.createdBy}`);
});
```

</CodeGroup>
