# Policy auf Version zurücksetzen

Setzen Sie eine Policy auf eine zuvor gespeicherte Version zurück. Die Engine tauscht die aktive Version atomar aus, sodass nachfolgende Evaluierungsanfragen sofort die Zielversion verwenden. Das Zurücksetzen wird als neuer Versionseintrag in der Historie aufgezeichnet.

## Endpunkt

`POST /api/v1/policies/{policyId}/rollback`

## Erforderliche Rolle

`MEMBER`

## Pfad-Parameter

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `policyId` | `string` | Ja | Die interne UUID der zurückzusetzenden Policy. |

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `Content-Type` | `application/json` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

## Request-Body

```json
{
  "targetVersion": 0,
  "reason": "string"
}
```

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `targetVersion` | `number` | Ja | Die wiederherzustellende Versionsnummer. Muss eine positive ganze Zahl sein, die in der Versionshistorie der Policy existiert. Verwenden Sie den [versions-Endpunkt](/de/docs/api/policies/versions), um verfügbare Versionen aufzulisten. |
| `reason` | `string` | Nein | Menschenlesbare Erklärung für das Zurücksetzen. Wird im für diese Operation erstellten Versionshistorie-Eintrag gespeichert. Nützlich für Audit-Trails. |

## Response-Body

```json
{
  "success": true,
  "previousVersion": 3,
  "currentVersion": 1
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `success` | `boolean` | `true`, wenn das Zurücksetzen abgeschlossen ist und die Policy nun die Zielversion bedient. |
| `previousVersion` | `number` | Die Versionsnummer, die unmittelbar vor diesem Zurücksetzen aktiv war. |
| `currentVersion` | `number` | Die Versionsnummer, die nach dem Zurücksetzen jetzt aktiv ist. Stimmt mit `targetVersion` aus der Anfrage überein. |

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Zurücksetzen abgeschlossen. Die Policy bedient nun `targetVersion`. |
| `400 Bad Request` | Fehlerhafter Request-Body, fehlendes `targetVersion` oder `targetVersion` existiert nicht in der Versionshistorie. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `MEMBER`-Rolle. |
| `404 Not Found` | Keine Policy für die angegebene `policyId` innerhalb des Mandanten gefunden. |
| `409 Conflict` | Die angeforderte `targetVersion` ist bereits die aktive Version. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler. Die aktive Version bleibt unverändert, wenn dieser Status zurückgegeben wird. |

## Beispiele

<CodeGroup>

```bash [curl]
curl -X POST \
  "https://policy.aster-lang.dev/api/v1/policies/d4e5f6a7-b8c9-4d0e-1f2a-3b4c5d6e7f8a/rollback" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "X-Tenant-ID: acme-corp" \
  -d '{
    "targetVersion": 1,
    "reason": "Version 3 caused incorrect rejections for applicants with income between 45000-49999. Rolling back pending investigation."
  }'
```

```js [JavaScript]
const policyId = 'd4e5f6a7-b8c9-4d0e-1f2a-3b4c5d6e7f8a';

const response = await fetch(
  `https://policy.aster-lang.dev/api/v1/policies/${policyId}/rollback`,
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer <token>',
      'Content-Type': 'application/json',
      'X-Tenant-ID': 'acme-corp',
    },
    body: JSON.stringify({
      targetVersion: 1,
      reason:
        'Version 3 caused incorrect rejections for applicants with income between 45000-49999. Rolling back pending investigation.',
    }),
  }
);

const data = await response.json();

if (data.success) {
  console.log(
    `Rolled back from v${data.previousVersion} to v${data.currentVersion}`
  );
} else {
  console.error('Rollback failed');
}
```

</CodeGroup>

### Beispiel-Antwort

```json
{
  "success": true,
  "previousVersion": 3,
  "currentVersion": 1
}
```

### Beispiel-Antwort (Ziel bereits aktiv)

HTTP `409 Conflict`:

```json
{
  "success": false,
  "error": "Version 3 is already the active version for policy 'd4e5f6a7-b8c9-4d0e-1f2a-3b4c5d6e7f8a'"
}
```
