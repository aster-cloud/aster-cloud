# Policy-Existenz validieren

Prüfen Sie, ob eine durch Modul- und Funktionsnamen identifizierte Policy bereitgestellt und aufrufbar ist. Dieser Endpunkt führt keinerlei Policy-Logik aus; er bestätigt lediglich, dass die Policy registriert und in einem ausführbaren Zustand ist.

Nutzen Sie diesen Endpunkt, um eine Evaluierungsanfrage vorab zu prüfen, eine erfolgreiche Bereitstellung zu verifizieren oder Health-Checks für kritische Policies zu implementieren.

## Endpunkt

`POST /api/v1/policies/validate`

## Erforderliche Rolle

`MEMBER`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `Content-Type` | `application/json` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

## Request-Body

```json
{
  "policyModule": "string",
  "policyFunction": "string"
}
```

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `policyModule` | `string` | Ja | Vollqualifizierter Modulname für die Suche (z. B. `"Loan.Approval"`). |
| `policyFunction` | `string` | Ja | Zu validierender Funktionsname innerhalb des Moduls (z. B. `"isEligible"`). |

## Response-Body

```json
{
  "valid": true,
  "error": null
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `valid` | `boolean` | `true`, wenn die Policy existiert, bereitgestellt und aufrufbar ist. `false`, wenn sie nicht gefunden wird, in einem fehlgeschlagenen Bereitstellungszustand ist oder anderweitig nicht aufrufbar ist. |
| `error` | `string \| null` | Beschreibender Grund, warum `valid` `false` ist; `null`, wenn `valid` `true` ist. |

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Validierungsprüfung abgeschlossen. Eine `200`-Antwort mit `valid: false` bedeutet, dass die Policy nicht existiert oder nicht aufrufbar ist — dies ist eine erfolgreiche Prüfung, kein HTTP-Fehler. |
| `400 Bad Request` | Fehlerhafter Request-Body oder fehlende Pflichtfelder. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `MEMBER`-Rolle. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler verhinderte den Abschluss der Prüfung. |

## Beispiele

<CodeGroup>

```bash [curl]
curl -X POST https://policy.aster-lang.dev/api/v1/policies/validate \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "X-Tenant-ID: acme-corp" \
  -d '{
    "policyModule": "Loan.Approval",
    "policyFunction": "isEligible"
  }'
```

```js [JavaScript]
const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/policies/validate',
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer <token>',
      'Content-Type': 'application/json',
      'X-Tenant-ID': 'acme-corp',
    },
    body: JSON.stringify({
      policyModule: 'Loan.Approval',
      policyFunction: 'isEligible',
    }),
  }
);

const data = await response.json();

if (!data.valid) {
  console.error('Policy is not callable:', data.error);
} else {
  console.log('Policy is ready for evaluation.');
}
```

</CodeGroup>

### Beispiel-Antwort (Policy gefunden)

```json
{
  "valid": true,
  "error": null
}
```

### Beispiel-Antwort (Policy nicht gefunden)

```json
{
  "valid": false,
  "error": "No deployed policy found for module 'Loan.Approval', function 'isEligible'"
}
```

### Beispiel-Antwort (Policy in fehlgeschlagenem Zustand)

```json
{
  "valid": false,
  "error": "Policy 'Loan.Approval.isEligible' exists but failed to load: compilation error in version 3"
}
```
