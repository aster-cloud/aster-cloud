# Policy evaluieren

Evaluieren Sie eine bereitgestellte Policy anhand von Modul- und Funktionsname. Die Policy muss bereits in der Engine bereitgestellt sein, bevor sie über diesen Endpunkt aufgerufen werden kann.

## Endpunkt

`POST /api/v1/policies/evaluate`

## Erforderliche Rolle

`MEMBER`

## Header

| Header | Wert | Erforderlich |
|--------|-------|----------|
| `Authorization` | `Bearer <token>` | Ja |
| `Content-Type` | `application/json` | Ja |
| `X-Tenant-ID` | Mandanten-Identifikator-String | Ja |

## Request-Body

```json
{
  "policyModule": "string",
  "policyFunction": "string",
  "context": [{}]
}
```

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `policyModule` | `string` | Ja | Der vollqualifizierte Modulname, wie er im CNL-Quellcode deklariert ist (z. B. `"Loan.Approval"`). |
| `policyFunction` | `string` | Ja | Der Funktionsname innerhalb des Moduls, der aufgerufen werden soll (z. B. `"isEligible"`). |
| `context` | `array<object>` | Ja | Eine geordnete Liste von Argument-Objekten, die positional an die Policy-Funktion übergeben werden. Die Struktur jedes Objekts muss dem in der Policy deklarierten Parameter-Schema entsprechen. Für parameterlose Funktionen ein leeres Array `[]` übergeben. |

## Response-Body

```json
{
  "result": "<any>",
  "executionTimeMs": 0,
  "error": null,
  "decisionTrace": null
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `result` | `any` | Der von der Policy-Funktion zurückgegebene Wert. Der Typ entspricht dem deklarierten Rückgabetyp der Funktion (boolean, number, string oder object). |
| `executionTimeMs` | `number` | Wanduhrzeit in Millisekunden vom Empfang der Anfrage bis zum Versand der Antwort. |
| `error` | `string \| null` | Menschenlesbare Fehlermeldung, wenn die Evaluierung fehlschlug; `null` bei Erfolg. |
| `decisionTrace` | `object \| null` | Strukturierter Trace der Regel-Evaluierungsschritte. Für diesen Endpunkt immer `null`. Verwenden Sie `/evaluate-source?trace=true`, um einen Trace zu erhalten. |

## HTTP-Statuscodes

| Status | Bedeutung |
|--------|---------|
| `200 OK` | Evaluierung abgeschlossen. Prüfen Sie das `error`-Feld — ein Nicht-null-Wert zeigt einen Policy-Fehler an, während der HTTP-Aufruf selbst erfolgreich war. |
| `400 Bad Request` | Fehlerhafter Request-Body oder fehlende Pflichtfelder. |
| `401 Unauthorized` | Fehlender oder ungültiger Bearer-Token. |
| `403 Forbidden` | Token ist gültig, dem Aufrufer fehlt jedoch die `MEMBER`-Rolle. |
| `404 Not Found` | Keine bereitgestellte Policy passend zu `policyModule` + `policyFunction` gefunden. |
| `500 Internal Server Error` | Unerwarteter Engine-Fehler. |

## Beispiele

<CodeGroup>

```bash [curl]
curl -X POST https://policy.aster-lang.dev/api/v1/policies/evaluate \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "X-Tenant-ID: acme-corp" \
  -d '{
    "policyModule": "Loan.Approval",
    "policyFunction": "isEligible",
    "context": [
      {
        "applicantAge": 30,
        "annualIncome": 75000,
        "creditScore": 720,
        "requestedAmount": 25000
      }
    ]
  }'
```

```js [JavaScript]
const response = await fetch(
  'https://policy.aster-lang.dev/api/v1/policies/evaluate',
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer <token>',
      'Content-Type': 'application/json',
      'X-Tenant-ID': 'acme-corp',
    },
    body: JSON.stringify({
      policyModule: 'Loan.Approval',
      policyFunction: 'isEligible',
      context: [
        {
          applicantAge: 30,
          annualIncome: 75000,
          creditScore: 720,
          requestedAmount: 25000,
        },
      ],
    }),
  }
);

const data = await response.json();
// data.result  → true | false | number | string | object
// data.error   → null on success
```

</CodeGroup>

### Beispiel-Antwort

```json
{
  "result": true,
  "executionTimeMs": 4,
  "error": null,
  "decisionTrace": null
}
```
