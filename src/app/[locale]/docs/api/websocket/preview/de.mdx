# WebSocket-Preview-Endpunkt

Der Preview-WebSocket-Endpunkt erlaubt Entwicklern, CNL-Policy-Quellcode in Echtzeit zu evaluieren, ohne ihn in der Engine bereitzustellen. Er ist für interaktives Tooling wie Editoren, Playgrounds und CI-Preview-Jobs gedacht. Die Verbindung läuft unter einem fest codierten `preview`-Mandanten und erfordert keine Authentifizierung.

<Callout type="warning" title="Preview-Mandant">
Alle Evaluierungen auf diesem Endpunkt werden unter dem eingebauten `preview`-Mandanten ausgeführt. Ergebnisse sind von den Daten produktiver Mandanten und bereitgestellten Policies isoliert. Verwenden Sie diesen Endpunkt nicht in Produktions-Workflows.
</Callout>

## Endpunkt

`ws://<host>/ws/preview`

Für TLS-gesicherte Bereitstellungen verwenden Sie `wss://`.

## Authentifizierung

Dieser Endpunkt erfordert **keine** Authentifizierung. Der WebSocket-Handshake schließt ohne Token- oder HMAC-Header ab. Alle Anfragen werden unter dem festen `preview`-Mandanten-Kontext ausgeführt.

<Callout type="tip">
Da der Preview-Endpunkt die Standard-HMAC-Signierung und RBAC-Erzwingung umgeht, sollte er nur in der Entwicklung oder hinter einer internen Netzwerkgrenze exponiert werden. Er ist nicht für die Produktion gedacht.
</Callout>

## Protokoll

Die Sitzung folgt einem einfachen Request-Response-Modell über eine einzige persistente Verbindung. Der Server sendet sofort nach Abschluss des Handshakes eine `connected`-Statusnachricht. Der Client sendet dann Evaluierungsanfragen; der Server antwortet auf jede einzeln.

### Client-Nachricht

```json
{
  "policyModule": "Loan.Approval",
  "policyFunction": "isEligible",
  "context": [
    {
      "applicantAge": 30,
      "annualIncome": 75000,
      "creditScore": 720,
      "requestedAmount": 25000
    }
  ]
}
```

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `policyModule` | `string` | Ja | Der vollqualifizierte Modulname, wie er im CNL-Quellcode deklariert ist (z. B. `Loan.Approval`). |
| `policyFunction` | `string` | Ja | Die Funktion innerhalb des Moduls, die aufgerufen werden soll. |
| `context` | `array<object>` | Ja | Geordnete Liste von Argument-Objekten, die positional an die Policy-Funktion übergeben werden. Für parameterlose Funktionen ein leeres Array `[]` übergeben. |

### Server-Nachrichten

#### Verbindungsbestätigung

Wird einmal sofort nach erfolgreichem Handshake gesendet.

```json
{
  "status": "connected",
  "message": "Connected to Aster preview endpoint"
}
```

#### Erfolgreiche Evaluierung

```json
{
  "status": "success",
  "message": null,
  "result": true,
  "executionTime": 6
}
```

#### Evaluierungsfehler

```json
{
  "status": "error",
  "message": "Policy function 'isEligible' not found in module 'Loan.Approval'",
  "result": null,
  "executionTime": null
}
```

### Felder der Server-Nachricht

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `status` | `string` | Einer von `connected`, `success` oder `error`. |
| `message` | `string \| null` | Menschenlesbare Beschreibung. Nicht-`null` für die Status `connected` und `error`; `null` bei `success`. |
| `result` | `any \| null` | Der von der Policy-Funktion zurückgegebene Wert. Stimmt mit dem deklarierten Rückgabetyp der Funktion überein. `null` bei Fehler. |
| `executionTime` | `number \| null` | Wanduhr-Evaluierungszeit in Millisekunden. `null` bei Fehler. |

## Verbindungs-Lifecycle

1. Client öffnet eine WebSocket-Verbindung zu `ws://<host>/ws/preview`.
2. Server sendet eine `{ "status": "connected" }`-Nachricht.
3. Client sendet eine JSON-Evaluierungsanfrage.
4. Server antwortet mit `{ "status": "success" }` oder `{ "status": "error" }`.
5. Schritte 3-4 wiederholen sich während der Sitzung.
6. Beide Parteien können die Verbindung jederzeit schließen.

## Beispiele

<CodeGroup>

```js [Browser]
const ws = new WebSocket('wss://policy.aster-lang.dev/ws/preview');

ws.addEventListener('open', () => {
  console.log('WebSocket open — awaiting connected message');
});

ws.addEventListener('message', (event) => {
  const msg = JSON.parse(event.data);

  if (msg.status === 'connected') {
    // Send an evaluation request once connected
    ws.send(JSON.stringify({
      policyModule:   'Loan.Approval',
      policyFunction: 'isEligible',
      context: [
        {
          applicantAge:    30,
          annualIncome:    75000,
          creditScore:     720,
          requestedAmount: 25000,
        },
      ],
    }));
  } else if (msg.status === 'success') {
    console.log('Result:', msg.result);
    console.log('Execution time:', msg.executionTime, 'ms');
    ws.close();
  } else if (msg.status === 'error') {
    console.error('Evaluation error:', msg.message);
    ws.close();
  }
});

ws.addEventListener('close', (event) => {
  console.log('Connection closed', event.code, event.reason);
});
```

```js [Node.js (ws)]
import WebSocket from 'ws';

const ws = new WebSocket('wss://policy.aster-lang.dev/ws/preview');

ws.on('message', (data) => {
  const msg = JSON.parse(data.toString());

  if (msg.status === 'connected') {
    ws.send(JSON.stringify({
      policyModule:   'Loan.Approval',
      policyFunction: 'isEligible',
      context: [
        {
          applicantAge:    30,
          annualIncome:    75000,
          creditScore:     720,
          requestedAmount: 25000,
        },
      ],
    }));
  } else if (msg.status === 'success') {
    console.log('Result:', msg.result);
    ws.close();
  } else if (msg.status === 'error') {
    console.error('Error:', msg.message);
    ws.close();
  }
});

ws.on('error', console.error);
```

</CodeGroup>

## WebSocket-Schließcodes

| Code | Bedeutung |
|------|---------|
| `1000` | Normales Schließen — Client oder Server hat die Verbindung absichtlich geschlossen. |
| `1011` | Unerwarteter Server-Fehler — interner Engine-Fehler. |
